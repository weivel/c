The repo root of the C layer: one CMake project in C11 with no compiler extensions and no dependency beyond the C library, the platform's loader and its threads. The layer's sources are built twice: `weivel_c` is the static library, position-independent so a shared library can link it in, and `weivel_c_shared` the shared library, its file named `weivel_c` and exporting only what the public headers mark `WEIVEL_C_API`, its import library in the build's `shared` directory, because on Windows it would otherwise carry the static library's name in the same place. The layer is compiled against the core's `weivel/core.h`, found under `siblings/core/include` unless `WEIVEL_C_CORE_INCLUDE_DIRECTORY` says otherwise, and the standard's `weivel/library.h` for its declaration types alone, found under `siblings/standard/include` unless `WEIVEL_C_STANDARD_INCLUDE_DIRECTORY` says otherwise; it links neither. When the standard's checkout is under `siblings/standard`, or `WEIVEL_C_STANDARD_SOURCE_DIRECTORY` names one, the optional `weivel_c_standard` and `weivel_c_standard_shared` are built from it as well, linking the standard's `weivel_standard` and `weivel_standard_shared`, and `weivel_c_conformance` linking `weivel_standard`; the tests need them. `weivel_c_benchmarks` is always built. Only when the layer is the top-level project are the tests added, with `weivel_c_testing`, the layer's sources built with `WEIVEL_C_TESTING`, which lets a test refuse or count the closes of a C library's binary and refuse a library service's registration. Every target is built with warnings as errors (`/W4 /WX /utf-8` on MSVC, `-Wall -Wextra -Wpedantic -Werror` elsewhere), and programs and shared libraries land in the build's `bin` directory, inside a folder per configuration (`bin/Debug`) under a multi-configuration generator such as Visual Studio's. `repo.json` pins `core`, `standard` and `conformance` by commit under `siblings/`. CI checks them out there; locally, link or clone each checkout into `siblings/`. The tests build the pinned core as a shared library and load it, and read the kit's layer vectors from `siblings/conformance` unless `WEIVEL_C_KIT_DIRECTORY` names another checkout. Build and test with `cmake -S . -B build`, `cmake --build build --config Debug` and `ctest --test-dir build --output-on-failure -C Debug`; CI runs that on Linux, Windows and macOS, once more on Linux under the address and undefined behaviour sanitizers and once under the thread sanitizer, and runs the benchmark gates in a Release build ([how](../benchmarks.md)). Its Drift job runs the conformance kit's `purity`, `names`, `parity` and `layers` checks on this repository at the kit commit it pins, each stated in the kit's `docs/checks.md`. Nothing is published: a consumer builds the layer from a pinned commit.
